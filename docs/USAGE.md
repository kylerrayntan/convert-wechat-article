# 使用说明

## 转换与复制

1. 准备 `.docx`：公式应为 Word 原生公式，图片应为内嵌 PNG/JPEG。
2. 按 README 安装依赖并运行转换。输出路径使用一个尚不存在的新目录。
3. 再运行 `verify.py`，确认通过。
4. 用 Safari 打开输出目录中的 `article.html`，待图片加载完成，点击 **Copy All**。
5. 在微信公众号正文区域粘贴，等待图片上传完成，点击 **Save as draft**，再通过 **Preview** 检查公式、图片和段落。

首次使用时先选一篇代表性文章验证保存、重新打开后的结果。复制成功提示只表示本地复制调用的结果，不表示公众号已经接收所有内容。

## 字号与图片清晰度

```sh
python3 convert-wechat-article/scripts/convert.py '/absolute/article.docx' \
  --output './local-output/article-02' \
  --font-px 17 --paragraph-after-px 24 --scale 6
```

公式按字体尺寸排版，以 6 倍像素生成，再按较小的排版尺寸显示。`--scale` 可选 3、4、6。调字号或段距后应重新转换整篇，以便校验参数与页面一致。

默认公式最大显示宽度为 351px。超宽会报错，不会自动缩小字号；需要人工确认数学上合理的分行方式。只有明确使用更宽版面时才调整 `--max-formula-width-px`。

原图不重新编码、不降采样；原图本来不清楚时不能凭空补出细节。公众号可能再次处理图片，因此以保存后的预览为准。

## 输出文件

| 文件 | 用途 |
| --- | --- |
| `article.html` | 自包含页面，整篇复制入口 |
| `assets/originals/` | 与 DOCX 内图片逐字节一致的原图 |
| `assets/formulas/` | 生成的高清公式 PNG |
| `manifest.json` | 内容顺序、公式表达式、参数、来源与资产哈希 |
| `report.json` | 校验结果和运行环境 |
| `failure.json` | 失败时的错误说明；失败目录不提供文章 HTML |

## 常见问题

**Copy All 没有完成复制**：点击 **Select Article**，再用系统复制快捷键（Mac 为 ⌘C），在公众号正文粘贴。页面里的选择操作是整篇选择，无需逐个复制公式。

**公众号中公式变成普通文字**：确认复制的是生成页面的文章，而不是聊天回复中的公式源码，也不是选择“粘贴并匹配样式”。确认复制载荷和实际粘贴结果，保留可复现信息。

**提示不支持公式结构或表格**：看 `failure.json` 中的具体节点，当前工具不能通过删除内容绕过。长公式不一定不支持，短根号公式也可能属于未适配的结构。

**找不到 Node 或依赖**：确认 `node --version`、`npm --version`，在仓库根目录重新执行 README 中的 `npm ci`。Node 不在 PATH 时，可给转换命令增加 `--node '/absolute/path/to/node'`。

**输出目录已存在**：换一个新目录名，工具不会覆盖旧结果。

**校验通过是否保证数学完全正确**：校验可检测丢失、篡改、数量和排版尺寸问题，不能独立证明数学等价；新结构仍需对照源公式检查。
